# Ying Teaching Hub — student login rollout (23 พ.ย. 2569)

## เป้าหมาย
- นักเรียนล็อกอินโดยใช้ **รหัสประจำตัวนักเรียน** เป็น Username
- ครูได้รับรหัสผ่านเริ่มต้นแบบสุ่มเฉพาะคนจากระบบ หลังเพิ่มบัญชี
- **บังคับเปลี่ยนรหัสผ่านครั้งแรกก่อนคืน access token** สำหรับเข้าสู่หน้าสมุดคะแนน
- นักเรียนอ่านได้เฉพาะข้อมูลส่วนตัวและคะแนนที่ครูเผยแพร่ (Supabase RLS)
- สื่อสาธารณะบน GitHub Pages ยังคงเปิดได้โดยไม่ล็อกอิน
- ใช้ Supabase โปรเจกต์เดิม `ying-teaching-hub` ที่ Sydney (ไม่เพิ่มโปรเจกต์หรือค่าใช้จ่าย)

## สถาปัตยกรรม
- Frontend `/classroom/student/`: รับ Student ID + password; จัดเก็บ Auth session เฉพาะแท็บ `sessionStorage`; โหลดข้อมูลผ่าน JWT + RLS
- Frontend `/classroom/students/`: ครูที่ผ่าน Auth + role check เห็นเฉพาะห้องที่ตนรับผิดชอบ และสร้างบัญชีนักเรียนทีละคน
- Edge Function `yth-student-auth`: ค้น ID -> Auth alias เฉพาะฝั่งเซิร์ฟเวอร์ (ไม่ส่งอีเมลแฝงไปยังหน้าเว็บ); rate limit; verify teacher JWT; generate random temporary password
- DB migrations: `20261123_yth_student_auth.sql`, `20261123_yth_student_alias_registration.sql`. โปรไฟล์นักเรียน RLS self + ครูของห้อง; alias เก็บใน `yth_internal`
- Role: ใช้ `yth_user_roles` เดิม (teacher/learner/admin) และสมาชิกห้อง `yth_class_memberships` เดิม; ไม่สร้างตาราง role ที่ซ้ำซ้อน

## สถานะก่อนเปิดใช้จริง
- เมื่อเริ่มงาน **Auth Users = 0**, โปรเจกต์ Supabase ACTIVE_HEALTHY, ตารางห้องและเนื้อหายังไม่มีข้อมูลจริง
- ต้องยืนยันอีเมลครูพี่หญิงและเชิญสร้างบัญชีผ่าน Supabase Dashboard > Authentication > Users จากนั้นผู้ดูแลกำหนด role `teacher` ใน `yth_user_roles`
- ผู้ดูแลสร้าง course/class ม.2 และ ม.4 และกำหนด `teacher_uid` ให้ตรงกับครูจริง และ `active=true` จึงจะเพิ่มนักเรียนได้
- ต้องมีรายชื่อนักเรียนยืนยัน (รหัส ชื่อ นามสกุล ห้อง) ก่อนนำเข้าบัญชี
- ห้ามสร้างบัญชีครูหรือใช้รหัสผ่านสมมติแล้วรายงานว่าใช้จริง
- **ยังไม่มีการทดสอบล็อกอินด้วยบัญชีครูหรือนักเรียนจริง** จนกว่าจะสร้างบัญชีที่ได้รับการยืนยัน

## เปิดใช้งานอย่างปลอดภัย
1. เชิญครูผ่าน <https://supabase.com/dashboard/project/zutekwbsqdhcnvcppvjx/auth/users> แบบส่วนตัว ไม่ใส่รหัสผ่านใน GitHub
2. เมื่อผู้ดูแลยืนยัน `auth.users.id` ให้กำหนด role teacher ผ่าน SQL editor:
   `insert into public.yth_user_roles(user_id,role) values ('<verified-uuid>'::uuid,'teacher') on conflict(user_id) do update set role='teacher';`
3. สร้าง course + class สำหรับ ม.2/ม.4 พร้อมระบุครูผู้รับผิดชอบและสถานะ active ในตารางเดิม; ตรวจสอบความถูกต้องก่อน
4. ครูเปิด `/classroom/login/` และ `/classroom/students/`, ลงทะเบียนนักเรียนทีละคน และส่งรหัสผ่านเริ่มต้นให้เจ้าของบัญชีโดยตรง
5. ทดสอบกรณีไม่สามารถล็อกอินด้วยรหัสผิด, ไม่มีสิทธิ์ครู, ต้องเปลี่ยนรหัสผ่านครั้งแรก, ปิดแท็บแล้วเซสชันหาย, นักเรียน A ไม่เห็นคะแนน B และไม่มีคะแนนที่ยังไม่เผยแพร่
6. ตรวจสอบ RLS policies, Security Advisors, มือถือ iPhone และปริมาณการใช้งาน Supabase Free

## ข้อจำกัด/ความปลอดภัย
- ไม่มีระบบนักเรียนสมัครเอง; การสร้างบัญชีต้องผ่านครูที่เป็นเจ้าของห้อง
- ไม่มีรายชื่อ รูปถ่าย หมายเลขนักเรียนหรือรหัสผ่านถูก commit ลง GitHub
- มีการจำกัดจำนวนการทดลองเข้าสู่ระบบต่อบัญชีและเครือข่ายในช่วง 15 นาที; ควรเพิ่ม CAPTCHA หากพบการโจมตี
- รหัสผ่านเริ่มต้นแสดงให้ครูเพียงครั้งเดียว, ไม่บันทึก plaintext ใน DB
- การเปลี่ยนรหัสผ่านก่อนเข้าสู่ระบบจริงดำเนินการฝั่งเซิร์ฟเวอร์; ไม่ส่ง token กลับจนกว่าจะเปลี่ยน
- การเข้าสู่ระบบครูที่แสดงตรงหัวห้องหมายถึงสถานะของเบราว์เซอร์นี้ **ไม่ใช่การติดตาม presence ของครูจากทุกอุปกรณ์**
- ยังไม่มีระบบอัปโหลด/ตรวจงานจริง และตัวละคร 3D ยังเป็นตัวอย่าง; ไม่ให้เข้าใจว่าแสดงนักเรียนออนไลน์จริง
- การกู้รหัสผ่านนักเรียนต้องให้ผู้ดูแลตรวจสอบตัวตนและออก credential ใหม่อย่างปลอดภัยในระยะถัดไป
